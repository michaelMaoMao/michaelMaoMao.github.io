得物 Claude Code 工作流实践

得物后端工程师的 AI 编程工作流沉淀：Claude Code CLI 选型、模型插拔、多 Agent 主从架构、SDD。与你的 flow-deep/SDD 路线高度同源。

一、工具选型：两点认知

  1. AI 编程工具 = 脑（大模型 API）+ 手（提示词/工作流）

    • 脑决定上限，手决定下限
    • 大模型像发动机——标准化、可插拔，所有工具通用
    • 启示：随便选趁手工具，自行按场景选配”发动机”

  2. AI 编程工具领域无技术壁垒

    • A 的杀手特性，B 半个月内跟进
    • Claude Code 用 Claude Code 迭代 Claude Code（工具自举）

选型两点：①便捷支持模型插拔 ②积极维护者（商业化产品）
→ 选 Claude Code CLI

二、模型插拔：Shell 函数 + 环境变量（核心可复用方案）

自定义 Shell 函数 + 行内临时环境变量注入 LLM 配置，别名按场景切换：

别名：claude=GLM / kcc=Kimi / zcc=GLM / qcc=七牛 MiniMax。

关键环境变量：ANTHROPIC_BASE_URL / ANTHROPIC_AUTH_TOKEN / ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL / CLAUDE_CODE_SUBAGENT_MODEL / ANTHROPIC_SMALL_FAST_MODEL。

开源工具替代：farion1231/cc-switch。

三、开发环境：多屏 + GUI/TUI 衔接

理念：古板开发者，做不到 fire-and-forget，要白盒掌控——“AI 只能帮我写代码，不能帮我背锅”。AI 只当助手，最终代码要有自己的风格/审美/品味。

多屏布局：MacBook（浏览器/飞书）+ 中屏（IDE JetBrains 双栏 diff）+ 左竖屏（文档/TUI 辅助）。

GUI/TUI 衔接（IDE 为主轴）：IDE 切项目 → 点按钮 → 自动新建/切换 iTerm2 的 CC 会话终端，跟随项目目录。实现：Shell + AppleScript 自动化 iTerm2 + JetBrains 外部工具。

四、多 Agent 主从架构（成本取舍精华）

每个项目自动开 3 个常驻 CC 会话：

角色 位置 模型 职责
架构师 上屏（大） 贵模型（Claude） 聊需求/对方案/产任务列表
开发者1 左下 领域模型（前端模型） 落地方案
开发者2 右下 领域模型（后端模型） 落地方案

成本取舍：Claude 对方案（高质量），GLM/MiniMax 实施（低成本）。

“知人善用才是好 PM”——匹配现实组织架构（1 架构师 + 多中高级开发者）。

五、SDD 规范驱动开发（与 flow-deep 同源）

主从协作需要”对大模型友好的方案/任务文档”作为开发者输入。采用 SDD，模拟现实软件开发，拆 3 阶段：

阶段 内容 对应你的工具
proposal 需求对齐、方案设计、任务细化 flow-deep Stage 3 规划 / planning-with-files
apply 开发任务实施 flow-deep Stage 4 执行 / multi-agent
archive 功能验收、文档沉淀 flow-deep Stage 5 验证 + 5.8 经验沉淀

六、🔥 与你环境的强呼应

  1. 你正在用得物的方案：你的 Claude Code 环境就是 GLM（open.bigmodel.cn，见 CLAUDE.md/RTK），正是本文的 zcc 方案——你已经在用得物验证过的模型插拔路线。
  2. SDD 同源：本文 proposal/apply/archive 与你的 flow-deep（planning-with-files + SDD 增强）是同一思想的不同实现。
  3. 多 Agent 主从：你的 multi-agent skill 可借鉴”架构师贵模型 + 开发者领域模型”的成本取舍——这正是 CLAUDE_CODE_SUBAGENT_MODEL 环境变量的用武之地。

七、可迁移要点

  1. 模型插拔用环境变量，按场景切换别名单命令（成本/质量动态平衡）
  2. AI 只当助手不背锅——白盒掌控，保留人的审美和最终决策
  3. 多 Agent 成本取舍：贵模型规划，便宜模型实施
  4. SDD 三阶段让 Agent 协作有”对 LLM 友好的契约文档”
  5. GUI/TUI 衔接用 AppleScript/外部工具自动化，减少切换割裂感

八、一句话

选 Claude Code 不是因为它最强，而是因为它”模型可插拔 + 商业化积极迭代”——把”脑”（模型）和”手”（工具）解耦，按场景为不同任务配不同发动机，再用 SDD 让多 Agent 协作有契约。这与你 flow-deep 的”确定性机制 + 模型语义”分工、planning-with-files 的契约化是同一条路。
