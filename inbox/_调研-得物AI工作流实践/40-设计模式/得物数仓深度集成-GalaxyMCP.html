得物数仓深度集成与 Galaxy MCP 实践（id=217）

得物数仓深度集成与 Galaxy MCP

Code LLM 在数仓的全链路集成系统论述。提出”数据确权 + 规范化I/O”两大支柱、”认知/执行运行时解耦”架构范式、Galaxy MCP 基础设施。与 Hermes 数仓（D3）是不同技术路线。

一、两大支柱

1. 数据确权（Data Rights Confirmation）

  • 管理审批（人类主导）：权限审批、合规定责、PII 审查、业务口径确认——AI 无民事主体资格，确权必须人工
  • 技术实现（AI 辅助）：DDL 脚本、同步任务配置、DQC 规则——基于已确权元数据自动生成，人工复核后上线

对应本系列”权限分级”（读/写/发布）和铁律——确权这类高风险决策牢牢握在人手里。

2. 规范化输入输出（Standardized I/O）= 数仓版 SDD

  • 规范化输入：结构化模板/CSV/JSON/API 喂给模型
  • 规范化输出：强制按 Markdown/DDL/报告框架交付
  • 把 LLM 不可控自由文本 → 基于规范契约的受限定向编译，从根源压缩幻觉

批判 Vibe Coding（凭感觉自由编码）——导致代码发散、口径不一致、数据失真、合规风险。

二、架构范式：认知/执行运行时解耦

运行时 载体 职责 接触数据
认知运行时 LLM 语义推演、需求→SQL 映射、规范校验、调优 仅操作已确权元数据+AST，不碰物理数据
执行运行时 Spark/Flink/ClickHouse 确定性算力调度、海量计算存储 物理扫描、分布式计算

这就是本系列铁律”模型做语义，引擎/代码做确定性执行”的数仓版精确表述。 LLM 不替代计算引擎，只做认知决策。

三、Galaxy MCP：给 LLM “手和眼”

MCP（Model Context Protocol）作为 LLM 与数仓的通信契约。Galaxy MCP 让 LLM 从”被动喂表结构”升级为”主动调 API 感知环境”：

  • HTTP Streamable 接口 + Bearer Token 鉴权
  • 核心工具集：分析数据结构（建表语句）、追溯血缘、逻辑审查（线上 SQL）、排查失败、根因分析（Spark 报错堆栈）、IDE 深度集成

四、工程实践（规范化 I/O 投射）

智能视觉埋点

  • 多模态输入（Gemini 1.5 Pro 读 UI 设计稿视觉特征）→ 标准化埋点提需文档
  • 三类资产注入：历史权威字典 + 埋点规范经验 + 埋点-指标血缘
  • Schema 强校验 JSON 输出（event_id 格式、参数收敛、完备性补全）
  • 效果：10 人日 → 5 人日，一致性 95%

AI OneData 建模

  • 血缘 CSV（脚本预提取）→ 标准 DDL 编译
  • 规范化输入避免模型读杂乱 SQL

五、🔥 与 Hermes 数仓（D3）的对比——不同路线

维度 D3 Hermes 数仓 id=217 Galaxy MCP
技术路线 Agent 框架（Nous Hermes） MCP 协议 + Code LLM（Claude Code）
核心机制 Skill 自学习沉淀规则 规范化 I/O 契约 + 工具调用
交互 单 Agent + 多能力模块 + 看板 LUI 意图驱动 + IDE 集成
适合 规则动态生长、经验资产化 规范明确、需感知真实数据环境

两者非互斥：MCP 提供”环境感知能力”，Hermes 提供”自学习沉淀能力”——数仓不同子场景可分别选用。再次印证”按场景选型”，甚至数仓内部都有多路线并存。

六、与你环境的强呼应

  1. MCP 同源：你的 Claude Code 环境大量用 MCP（Context7/Sequential/Playwright/Tavily/web-access），正是 Galaxy MCP 的同一协议思路——给 LLM 标准化的”手和眼”。
  2. SDD 同源：id=217 的”规范化 I/O 契约” = id=213 的 SDD = 你 flow-deep 的 SDD 增强，三者同源。
  3. 认知/执行解耦：你的”模型感知/代码计算”铁律 = id=217 的”认知/执行运行时解耦”，同一思想的数仓版。

七、可迁移要点

  1. 数据确权先行：AI 落地前先划清”管理审批（人）vs 技术实现（AI）”边界
  2. 规范化 I/O 压幻觉：结构化输入 + 强校验输出，拒绝 Vibe Coding
  3. MCP 给 LLM 手和眼：标准化协议让 LLM 安全调企业 API
  4. 认知/执行解耦：LLM 只做语义决策，不碰算力执行
