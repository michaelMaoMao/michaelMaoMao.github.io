LangGraph 核心机制与 interrupt/resume 代码

LangGraph 核心机制

一、设计目标（官方博客 L1）

Control（控制）+ Durability（持久化）

  • Control：结构化、确定性并发的执行模型，agent 严格按意图执行，输出变异永不归咎于框架
  • Durability：checkpointing（跨机器跨时间恢复）+ task queue（可靠重试）+ tracing（全程可观测），让 slow/flaky 的 LLM agent 也能在生产稳定运行

二、执行模型：BSP/Pregel（非 DAG）

  • 为什么不用 DAG？DAG 不支持循环，而 agent 需要 cycles（思考-行动-再思考）
  • 为什么不用 Temporal 类 durable engine？无 streaming，且历史越长越慢
  • Pregel 提供：确定性并发 + 完整支持循环 + 所有动作对历史 O(1)

三、三个核心抽象

抽象 作用
Channels 持有数据（任意 Python 类型）+ version（单调递增）
Nodes 函数，订阅一个或多个 channel，channel 变化即触发
Input/Output 映射 起始输入写到的 channel / 终止输出的 channel

每个 iteration 并行执行选定的 node（各自独立 state 副本），按确定性顺序合并更新 → 保证执行顺序与延迟波动不影响最终输出。

四、为什么离散步骤是 HITL 的基石（关键）

单函数 + while 循环无法序列化跨机器恢复。
拆成离散步骤后，checkpoint 保存序列化的 channel values → 可跨机器、跨任意时间恢复。

这正是 interrupt/resume 的底层支撑——也是得物活动搭建”关掉浏览器再打开能继续”的实现原理。

三个关键点

  1. interrupt(value)：节点内调用，value 推给前端，图暂停；其返回值是 resume 传回的数据
  2. Command(resume=data)：恢复执行，data 成为 interrupt() 的返回值
  3. checkpointer + thread_id：状态持久化，支持跨进程/跨时间恢复

六、对应得物活动搭建

得物的 6 个中断点 = 6 个 interrupt() 调用点，对应 LangChain 文档的三类 HITL 动作：

  • Approve/Reject（审批/拒绝）— 高风险操作前确认
  • Edit（编辑）— 人工修正 AI 输出
  • Respond/Input（补充）— 提供 AI 无法自行获取的数据

每个中断卡片 = 一个 interrupt payload，前端据此渲染；用户操作后 Command(resume) 推回，图从断点继续。

七、生产级要点

  • checkpointer 生产用持久化存储（PostgreSQL/Redis），非 InMemorySaver
  • thread_id 要稳定（用户会话级），保证恢复对应正确状态
  • interrupt 的 payload 要结构化（前端据此渲染卡片 + 解释”为什么需要你填”）
  • 配合 tracing（LangSmith）做全程可观测——对应本系列”执行可观测”保障层
