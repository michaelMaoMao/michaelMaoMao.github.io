interrupt/resume demo 落地验证

在本地 venv 跑通 interrupt_demo.py，实证 Phase 1 代码骨架真实可落地，复现得物活动搭建”6 中断点 + 中断恢复”核心机制。脚本见同目录 interrupt_demo.py。

环境

  • Python 3.11.4 / langgraph 1.2.6 / InMemorySaver（开发用，生产换 PostgreSQL）
  • venv 隔离在 /tmp/lg-venv（不污染系统 Python）

验证结果（运行输出）

第 1 轮：跑到 confirm 中断 ✓

  • parse 节点执行（模拟 LLM 生成草稿）
  • confirm 节点调 interrupt() → 图暂停
  • 输出 __interrupt__ 事件，value = 推给前端的 payload {draft, msg}
  • get_state 读取：next=('confirm',)，values 已含 draft（证明 checkpointer 持久化生效）

第 2 轮：Command(resume) 恢复 ✓

  • 传 Command(resume={approved, edited})
  • confirm 收到反馈（interrupt() 返回值 = resume 数据）
  • build 节点执行写操作（确认后才写，验证副作用延后原则）
  • 最终状态完整：draft + confirmed + result

验证的三个核心机制

机制 验证
interrupt(value) 暂停 图在 confirm 暂停，value 作为 payload 推出 ✓
Checkpointer 持久化 get_state 能读暂停点和已执行 values（同 thread_id 可跨进程恢复）✓
Command(resume) 恢复 resume 数据成为 interrupt() 返回值，图从断点继续 ✓

对应得物实践

demo 元素 得物活动搭建对应
confirm_node 的 interrupt() 得物 6 个中断点之一
interrupt 的 value payload 得物中断卡片的数据
Command(resume=…) 前端用户操作后推回
build 在 confirm 之后 得物”初始化无副作用，确认后才写”

结论

实现路径.md 的 Phase 1 代码骨架真实可落地。langgraph 1.2.6 的 interrupt/resume + checkpointer 在本地完整复现得物活动搭建核心。生产化只需三步：

  1. InMemorySaver → PostgreSQL/Redis checkpointer
  2. parse_node 的模拟 → 真实 LLM 调用
  3. 加 LangSmith tracing 做可观测
