Dify 工作流机制与得物第一版用法

Dify 工作流机制

一、Dify 是什么

开源 LLM 应用开发平台，核心理念 “Backend as a Service + LLMOps”。把构建大模型应用的关键技术栈（模型接入、RAG、工具编排、监控）集成好，让 AI 应用从原型快速走向生产。定位：LangChain 像”工具箱”（锤子钉子），Dify 像”精装修的脚手架”。

二、两种应用模式（核心）

类型 运行方式 起始节点 结束节点 适用场景
工作流 Workflow 从头到尾运行一次 用户输入 或 触发器 输出(可选) 自动报告、数据处理管道、批处理
对话流 Chatflow 每条消息触发流程 用户输入 直接回复(必需) 交互式助手、引导式问答

触发器（仅工作流）：按计划(cron)、Webhook、插件事件自动运行。

三、节点系统（搭积木式编排）

通过可视化画布拖拽、连接、配置节点构建流程，每个节点处理一个特定步骤：

  • LLM 节点：调用大模型
  • 知识检索 Knowledge Retrieval：RAG 检索
  • 条件分支 IF/ELSE：路由
  • 工具节点：调用外部工具/HTTP
  • 代码节点：自定义逻辑（Python/JS）
  • 模板转换：组装输出
  • 变量聚合器：合并多路结果

大部分工作无需写代码；只有现有节点满足不了才写。

四、Agent 节点的推理策略

Dify 的 Agent 节点支持三种：

  • Function Calling：结构化工具调用
  • ReAct（推理+行动）：需要外部知识的复杂任务
  • ReWOO（解耦推理）：先制定完整计划再执行，token 消耗更低

五、Agentic 工作流的设计哲学（Dify 官方表述）

AI 模型单独使用时不可预测（幻觉、遗漏步骤、输出不一致）。生产环境需要对 AI 运行方式有更多控制。Agentic 工作流通过把 AI 嵌入结构化、可重复的流程解决——设计流程逐步编排模型、工具、逻辑，包含明确的条件、检查点和回退路径。AI 仍承担重活，但在你定义的边界内运行。

这与得物”流程可控、正确率优先”、本系列”确定性机制锁定 + 模型只做语义”的铁律完全一致。

六、得物第一版怎么用 Dify（还原）

得物活动搭建第一版用 2 个 Dify Workflow：

  1. Workflow 1：把策划文档（飞书）解析成结构化字段
  2. Workflow 2：把解析结果与系统下拉选项做语义匹配

实现”AI 预填 + 人工校验”，运营从”全部手填”变成”AI 预填 + 校验”。

七、Dify 的能力边界（为何得物第二版换 LangGraph）

维度 Dify LangGraph
编排方式 可视化拖拽节点 代码定义图
上手成本 低（非技术人员可用） 中高（需写代码）
灵活度 受节点能力限制 任意（代码级控制）
状态持久化 平台内置 Checkpointer（可控）
中断恢复(HITL) 较弱 interrupt/resume 原生支持
适合阶段 快速验证/原型 生产级可控编排

得物换型逻辑：第一版用 Dify 快速验证”AI 能否帮填表”，跑通后发现”范式没变、组件硬编码、无持久化”，要质变需要代码级的可控编排 + interrupt/resume + Capability Registry → 第二版切 LangGraph。

八、可迁移结论

  • Dify 适合从 0 到 1 快速验证 AI 工作流想法（低代码、可视化、非技术可参与）
  • LangGraph 适合从 1 到 N 生产级落地（需可控状态机、人机中断、复杂扩展）
  • 两者非互斥：得物正是”Dify 验证 → LangGraph 生产”的典型路径
